# ความปลอดภัย

Nova สามารถควบคุม Windows session ที่กำลังเข้าสู่ระบบอยู่ จึงต้องถือว่า configuration, ไฟล์โมเดล Python environment และ source code ใน repository เป็นส่วนที่เชื่อถือได้ ส่วนเสียงและผลลัพธ์จากโมเดลต้องถือเป็น input ที่ไม่เชื่อถือเสมอ

## แบบจำลองภัยคุกคาม

ภัยที่เกี่ยวข้องประกอบด้วยบุคคลอื่นพูดใกล้ไมโครโฟน เสียงที่เล่นผ่านลำโพง เสียงโคลนหรือ deepfake เนื้อหาอันตรายในวิดีโอ การตรวจพบคำปลุกผิด การถอดเสียงผิด prompt injection ต่อ LLM การแทรกคำสั่งผ่าน path/URL การแก้ไข model artifact และมัลแวร์ที่ทำงานอยู่ใน session ของผู้ใช้

Nova ไม่สามารถป้องกันผู้โจมตีที่แก้ source/configuration แทนที่ model artifact ควบคุมบัญชี Windows หรือแทรกโค้ดเข้า Python process ได้

## การปลอมเสียงและ replay attack

ECAPA verification วัดความคล้ายของเสียง ไม่ใช่หลักฐานชีวมิติที่สมบูรณ์ เสียงบันทึก เสียงสังเคราะห์คุณภาพสูง voice conversion อาการป่วย การเปลี่ยนไมโครโฟน และเสียงรบกวน อาจทำให้ยอมรับหรือปฏิเสธผิด ค่า FAR/FRR จาก dataset ขนาดเล็กในเครื่องอาจไม่สะท้อนผลเมื่อถูกโจมตีจริง

Challenge-response แบบตัวเลือกช่วยลดประโยชน์ของเสียงบันทึกตายตัว โดยให้ผู้ใช้พูดวลีสุ่ม แต่เป็นเพียงการป้องกันพื้นฐาน ระบบโคลนเสียงแบบสดยังตอบได้ และ implementation นี้ไม่มีโมเดล anti-spoofing/liveness หรือระบบตรวจแหล่งเสียงสะท้อนที่น่าเชื่อถือ ควรปิด shutdown/restart ไว้หากยังไม่ยอมรับความเสี่ยง ใช้หูฟังเมื่อเหมาะสม และล็อก Windows session เมื่อไม่อยู่หน้าเครื่อง

## LLM และ prompt injection

Ollama ปิดไว้โดยค่าเริ่มต้น หากเปิดใช้ เสียงใด ๆ อาจพยายามสั่งให้โมเดลละเลยกฎ Nova จะถือผลลัพธ์เป็นข้อมูล ตรวจสอบผ่าน `ActionPlan` ของ Pydantic ที่จำกัดชนิดและจำนวน action ปฏิเสธฟิลด์หรือ action ที่ไม่รู้จัก และส่งทุก action ผ่าน policy เดิม ข้อความสนทนาจึงไม่สามารถกลายเป็นโค้ดโดยตรง

ห้ามเพิ่มรูปแบบต่อไปนี้:

```python
os.system(model_text)
subprocess.run(model_text, shell=True)
```

Executor ปัจจุบันสร้าง argument array จาก executable ที่ตั้งค่าไว้และค่าที่ตรวจสอบแล้ว จากนั้นเรียก subprocess ด้วย `shell=False` ข้อความที่มี `;`, `&&`, `$()` หรือไวยากรณ์ PowerShell จึงยังเป็นเพียง argument เดียวและไม่กลายเป็นคำสั่งใหม่

## ระบบสิทธิ์

- ระดับ 0 จำกัดเฉพาะการควบคุมมีเดีย/เสียงที่มีผลกระทบต่ำ และการอ่านสถานะ
- ระดับ 1 ต้องเป็นเจ้าของที่ผ่านการตรวจสอบก่อนเปิดหรือปิด resource ที่กำหนด หรือบันทึกภาพหน้าจอ
- ระดับ 2 ต้องเป็นเจ้าของและผ่าน confirmation ที่หมดอายุได้ หาก `replay_protection.enabled` เป็นจริง จะต้องผ่านวลีสุ่มเพิ่มด้วย
- ระดับ 3 ปิดอยู่ และไม่มี action type/executor branch สำหรับงานทำลายข้อมูลหรือสั่งงานทั่วไป

Confirmation เก็บ action ที่รออยู่เพียงรายการเดียว มีเวลาหมดอายุ ผูกกับ token แบบสุ่ม และใช้ได้ครั้งเดียว การยืนยันหนึ่งครั้งจะไม่อนุญาต action อื่นหรือทั้ง multi-action plan

## ความปลอดภัยของ path, app และ URL

แอปและโปรเจกต์ต้องตรงกับ alias ใน YAML แบบไม่สนตัวพิมพ์เล็ก/ใหญ่ การปิดแอปจะจับคู่เฉพาะ process name ที่ตั้งไว้ โปรเจกต์และโฟลเดอร์ต้องมีอยู่จริง การเปิดเว็บอนุญาตเฉพาะ HTTP/HTTPS และคำค้นจะถูก URL-encode ระบบไม่มีตัวลบไฟล์ shell ทั่วไป installer การส่งข้อความ หรือ executor สำหรับปรับค่าระบบทั่วไป

ควรระวัง app entry ที่ตั้ง executable เป็น shell, script host, package manager หรือ interpreter เพราะ allow-list จะปลอดภัยได้เท่ากับ target ที่กำหนดไว้เท่านั้น ควรจำกัดสิทธิ์เขียน YAML ให้เฉพาะเจ้าของ

## Log และเสียงบันทึก

Structured log มี transcript, intent, score, action, ระยะเวลา และ error ซึ่ง transcript อาจเป็นข้อมูลอ่อนไหว ควรป้องกันหรือหมุนเวียน `logs/nova.jsonl` ระบบไม่เก็บเสียงดิบโดยค่าเริ่มต้น และคำสั่งเก็บข้อมูลจะบันทึกเสียงหลังการโต้ตอบจากผู้ใช้โดยชัดเจนเท่านั้น เสียงฝึกและ embedding เป็นข้อมูลชีวมิติ/ข้อมูลส่วนบุคคล ควรเข้ารหัส backup และห้าม commit

## ค่าเริ่มต้นที่แนะนำ

1. ปิด `llm.enabled`, restart และ shutdown ไว้ก่อน และเปิด `replay_protection` ก่อนอนุญาต action ที่มีความเสี่ยงสูง
2. เปิด speaker verification หลังทำ enrollment เสร็จ
3. ใช้ negative speaker set ที่หลากหลายและแยกจากชุดฝึก แล้วเลือก threshold ที่ให้ FAR ต่ำ
4. เพิ่ม hard negative ของคำปลุกจากห้องที่ใช้งานจริง
5. ตรวจ executable/project path ทุกค่าและลบ alias ที่ไม่ใช้
6. รันด้วยบัญชี Windows มาตรฐาน ไม่ใช่ administrator
7. อัปเดต Windows, Python dependencies และโมเดลจากแหล่งที่เชื่อถือได้
8. ตรวจ JSON log เพื่อหาการปลุกผิดและ action ที่ถูกปฏิเสธโดยไม่คาดคิด

## ข้อจำกัดที่ทราบ

Speaker verification ไม่สามารถป้องกัน replay/deepfake ได้อย่างสมบูรณ์ VAD อาจตอบสนองต่อเสียงจากลำโพง ความแม่นยำของคำปลุกขึ้นกับข้อมูลที่เก็บในเครื่อง faster-whisper อาจสร้างข้อความหลอนหรือฟังผิด คุณภาพ TTS ภาษาไทยของ pyttsx3 ขึ้นกับเสียงที่ติดตั้งใน Windows และการเปิด browser/app จะได้รับสิทธิ์เท่ากับผู้ใช้ Windows ที่ล็อกอินอยู่ Confirmation ช่วยลดความผิดพลาด แต่ไม่ได้ทำให้การควบคุมด้วยเสียงเป็นระบบยืนยันตัวตนความมั่นคงสูง
