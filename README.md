# Nova: Personal Voice AI Assistant for Windows

Nova is a local-first Python voice assistant for Windows 10/11. It listens for a configurable wake phrase, verifies the speaker with ECAPA-TDNN embeddings, transcribes Thai or English locally with faster-whisper, maps speech to typed actions, applies permissions, and performs only explicitly supported Windows operations. No paid API is required.

The working pipeline is:

```text
Microphone -> VAD -> Wake word -> Speaker verification -> Command recording
           -> faster-whisper -> Intent/entity parsing -> Permissions
           -> Strict Windows executor -> Local TTS
```

The intent, custom wake-word, and speaker decision components are real trainable ML pipelines with saved metrics and evaluation commands. The optional Ollama adapter is disabled by default, and its JSON is Pydantic-validated before the same permission/executor boundary.

## Features

- Push-to-talk mode works without a wake-word model and is the recommended first test.
- Custom PyTorch wake-word CNN or an openWakeWord adapter.
- SpeechBrain `spkrec-ecapa-voxceleb` embeddings; cosine, logistic regression, SVM, and MLP verifier comparison.
- Thai/English faster-whisper transcription with automatic CUDA/CPU selection.
- Trainable multilingual character TF-IDF + logistic-regression intent classifier with deterministic fallback.
- Apps/projects configured in YAML; subprocesses always receive argument lists with `shell=False`.
- Four permission levels, owner checks, expiring confirmations, and optional challenge-response.
- Volume, media, browser, screenshot, lock, system status, and opt-in restart/shutdown actions.
- JSON-lines event logs without audio by default and a `--debug` terminal dashboard.

## Requirements

- 64-bit Windows 10 or Windows 11
- Python 3.11 or 3.12 (3.11 is the primary tested target)
- A working microphone
- About 3 GB disk space for a normal CPU setup; model choice can increase this
- Optional NVIDIA GPU with a PyTorch-compatible CUDA driver

## Installation

From PowerShell in the project directory:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
```

Or run the equivalent setup helper:

```powershell
.\scripts\setup.ps1
```

If PowerShell blocks local scripts for this session:

```powershell
Set-ExecutionPolicy -Scope Process Bypass
```

### CUDA

The default requirements install PyTorch, and Nova automatically uses CUDA when `torch.cuda.is_available()` is true. For a CUDA-specific PyTorch wheel, install the command generated by the official [PyTorch installation selector](https://pytorch.org/get-started/locally/) before `pip install -r requirements.txt`. Verify the result:

```powershell
python scripts/check_gpu.py
```

CUDA initialization failures in faster-whisper fall back to CPU/int8. For a smaller CPU footprint, set `stt.model: base` or `tiny` in `config/settings.yaml`.

## First configuration

1. List microphone indexes and set `audio.device` in `config/settings.yaml`:

   ```powershell
   python main.py --list-microphones
   ```

2. Edit `config/apps.yaml`. Prefer a full executable path; command names such as `code` work only when present on `PATH`.
3. Edit `config/projects.yaml` with real absolute directories.
4. Start with speaker verification off while checking the audio/STT path:

   ```powershell
   python main.py --push-to-talk --no-speaker-verification --debug
   ```

5. Collect and train speaker data, then collect/train the custom wake word. Full steps are in [TRAINING.md](TRAINING.md).

## Running

Normal wake-word mode (requires trained wake-word and speaker artifacts with the default settings):

```powershell
python main.py
```

Useful modes:

```powershell
python main.py --debug
python main.py --push-to-talk
python main.py --no-speaker-verification
python main.py --text "what time is it" --no-speaker-verification
```

Typed mode executes real permitted actions; use a read-only command such as `what time is it` for initial validation.

## Configuration map

- `config/settings.yaml`: audio, models, thresholds, TTS, optional Ollama, logging.
- `config/apps.yaml`: canonical names, aliases, executable paths, process names.
- `config/projects.yaml`: canonical names, aliases, absolute paths, editor.
- `config/permissions.yaml`: enabled state, level, confirmation, challenge.

Restart and shutdown are implemented but disabled by default. Enabling them still requires verified-speaker, challenge, and confirmation checks. Level-3 operations do not exist in `ActionType` or the executor even if a policy is accidentally added.

## Tests

The test suite mocks action effects and never locks, restarts, shuts down, or launches applications:

```powershell
pytest
```

Train and smoke-test the intent model:

```powershell
python -m intent.train
python -m intent.evaluate
python main.py --text "what time is it" --no-speaker-verification
```

## Troubleshooting

- **No microphone / PortAudio error:** run `python main.py --list-microphones`, choose an input index, and allow desktop microphone access in Windows Settings.
- **Wake model missing:** run the wake-word collection/training commands in `TRAINING.md`, or use `--push-to-talk`.
- **Speaker model missing:** complete enrollment/training, or temporarily use `--no-speaker-verification` during setup.
- **Application not found:** correct its `path`/`executable` in `config/apps.yaml`. Paths are never guessed.
- **Project path invalid:** use an existing absolute path in `config/projects.yaml`.
- **CUDA/DLL error:** run `python scripts/check_gpu.py`; set `device: cpu` under `stt` and `speaker` if necessary.
- **Thai TTS sounds wrong:** install a Thai Windows SAPI voice, inspect voices from Python/pyttsx3, and set `tts.voice` to part of its name or ID. TTS can be disabled without affecting commands.
- **Low wake recall / false triggers:** collect hard negatives, evaluate, then select a threshold from `runs/wakeword/.../threshold_evaluation.json`.
